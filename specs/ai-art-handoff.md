# AI Art Pipeline — Agent Handoff / Task Brief

You are picking up work in this repository. Read `AGENTS.md` first, then
`specs/generation-mac-instructions.md` (how the human runs generation on the
other Mac). This brief tells you what exists, what to build next, and the rules.

## Context

- This repo is a render-free Rust port of the OpenBounty engine plus a shell
  (`engine/`, `shell/`). Game rules and state live in `engine`; the shell draws.
- We are producing a **new, original, committed art pack** under `packs/open/`
  (CC0). It is independent artwork, not an upscale/trace of the original game
  art. See `NOTICES.md` and `packs/open/README.md`.
- The spec/contract for every renderable slot is `tools/hd_assets.json`
  (paths, native size, alpha, engine-used, draw order), generated by
  `tools/hd_manifest.py` from the pack + extraction.
- Procedural art generators exist (`tools/gen_terrain.py`, `gen_objects.py`,
  `gen_sprites.py`, `gen_troops.py`, `gen_villains.py`, `gen_combat.py`), but we
  are moving to an **AI (ComfyUI) painted look** for quality.

## Where things live (git-ignore awareness)

- Committed: `tools/`, `specs/`, `packs/open/` (art + provenance + LICENSE).
- Ignored: `reference/` (OpenBounty clone + the `kings-bounty` pack),
  `game-assets/` (extracted originals, AI staging, built packs), `target/`.
- AI staging output: `game-assets/ai-out/` (gitignored); never commit it.
- The extracted original art (`game-assets/extracted/art/...`) and the pack
  (`reference/assets/kings-bounty/`) exist only on machines where they were
  created/copied. They are NOT delivered by `git pull`.

## Environment split

- **Primary Mac** (this repo's main working copy): has `reference/` and
  `game-assets/extracted/` (the DOS art dump). Use it for measurements and for
  promoting art into `packs/open/`.
- **Generation Mac**: runs ComfyUI locally (Apple Silicon, free). Has the repo
  clone and `~/dev/ai/matte-venv` (rembg). It does NOT need the original art for
  character generation; it consumes committed specs via `git pull`.

ComfyUI assets (on the generation Mac): SDXL base checkpoint, `rembg[cpu]`,
ComfyUI_IPAdapter_plus + `ip-adapter-plus_sdxl_vit-h` + CLIP-ViT-H encoder.
The CLIP encoder must live at
`models/clip_vision/CLIP-ViT-H-14-laion2B-s32B-b63K...` (canonical name).

## The AI pipeline as built

`tools/gen_ai.py` (stdlib only; talks to `http://127.0.0.1:8188`):

- `probe` — lists checkpoints, matte node, clip_vision/ipadapter files, and
  reports `gen_ai version X`.
- `one <path>` — generate one slot.
- `batch --category <cat> [--only S] [--limit N] [--resume] [--sheet] [--no-clear]`
  — batch over `tools/hd_assets.json`, fault-tolerant, clears the ComfyUI queue
  first.
- `sheet` — writes `game-assets/ai-out/index.html` review contact sheet.

Global flags: `--host --ckpt --scale --seed --tries --denoise --ipadapter
--ip-weight --ip-preset --matte {cli,node,none} --rembg --matte-node --out`.

Key behaviour:

- **Non-square assets** are generated at an aspect-matched size (`gen_size`).
- **Animated units** (troops/villains/hero) render 4 frames: frame 0 txt2img,
  frames 1–3 img2img from frame 0 (`--denoise`, default 0.45), optionally
  conditioned on frame 0 via IP-Adapter (`--ipadapter`). Subject is matted with
  rembg, cropped to its blob, fitted to the cell. Facing right; the engine
  mirrors the AI side.
- **Castle** is one 3×2 image sliced into six aligned pieces.
- Prompts per role are in `prompt_all` / `frame_prompt` / `IDLE_POSES` /
  `WALK_POSES` / `TROOP` / `OBJECT` / `COMBAT` / `UI` dicts.

## Engine facts that constrain the art (already verified)

- Combat units loop a **4-frame IDLE** animation (`combat.h`: `frame // 0..3
  idle anim`); there is no separate move/attack animation. Movement is instant,
  attacks are a damage-splat overlay.
- Only the **AI side is mirrored** horizontally. Player art faces right.
- Tile art is **opaque**; sprites/objects are **colour-keyed** (need alpha).
- Native cell is 48×34; we author at `--scale 6` → 288×204 (or 8 → 384×272).
- The pack is built with `tools/open_pack.py build --scale N` and validated with
  `open_pack.py verify --scale N` (alpha convention, dimensions, provenance).

## Art direction (approved)

Smooth high-resolution hand-painted 2D fantasy strategy-game art; modern HD
remaster look; top-down/game-map presentation; clear silhouettes; no pixel art,
no visible pixelation, no isometric/hex/diorama reinterpretation. Preserve
topology, orientation, footprint and edge/transition direction. Objects have
transparent backgrounds with no baked terrain. See the negative/positive prompt
guidance in the human's brief (summarised in `gen_ai.py` prompts).

## What to build next (priority order)

### 1. Original-asset measurement → `tools/asset_layout.json`  (do this first)

The original colour-keyed art has a real alpha channel. Measure, per original
colour-keyed frame (troops, villains, classes, combat obstacles, objects), the
**bounding box, ground baseline, horizontal centre, and size as a fraction of
the 48×34 cell**, plus the **frame-to-frame motion** (centroid/bbox deltas).

- Input: `game-assets/extracted/art/...` (primary Mac only).
- Output: a committed JSON, e.g. `tools/asset_layout.json`, one entry per
  pack-relative path: `{bbox:[x0,y0,x1,y1], baseline, cx, cell:[48,34]}`.
- This is functional geometry, safe to commit and safe for the generation Mac
  to consume without the originals.

### 2. Registration-aware placement in `gen_ai.py`

Today `fit_sprite` scales the subject to *fill* the cell. Add a mode that uses
`asset_layout.json` to place the HD sprite so its **baseline, centre and height
fraction** match the original. This is the main fix for "troops inconsistent in
size/position". Provide `--registration spec|fill` (default `spec` once the
layout exists).

### 3. Optional global style reference

Add `--style-ref <path>`: upload one approved troop image and apply IP-Adapter
to **every** frame (not just frames > 0) so all 25 troops share one look. Keep
per-unit img2img for pose consistency.

### 4. Validation

`tools/validate_pack.py`:
- terrain: compose neighbours (ideally render a real window from
  `reference/.../maps/*.dat`) and flag seam discontinuities / wrong transition
  orientation;
- objects: check alpha present, footprint bounds, no baked terrain / stray
  scenery; no silent edits — report, don't fix.

## Rules

- Redesign, don't trace. Use originals for **functional geometry only**
  (topology, masks, bboxes, frame counts). Do not feed original *pixels* into
  ControlNet/img2img and call it non-derivative; keep expressive shapes
  independently authored. (Not legal advice.)
- Preserve RNG/marker semantics in the engine; never add renderer/UI crates to
  `engine/Cargo.toml`.
- `cargo fmt --all --check`, `cargo test --workspace` stay green.
- Commit only when the human asks. Conventional single-line messages.
- AI staging (`game-assets/ai-out`) and originals are never committed.

## Acceptance for the troop slice

- `gen_ai.py probe` reports the current version and a working IP-Adapter setup.
- `batch --category troops --ipadapter` yields, per troop, 4 frames that are the
  **same character** in **distinct idle poses**, facing right, alpha-cut,
  correct native frame count, and **registered** (baseline/size) per
  `asset_layout.json`.
- `open_pack.py verify --scale 6` passes once promoted into `packs/open/art`
  with provenance `method: ai-assisted`.
